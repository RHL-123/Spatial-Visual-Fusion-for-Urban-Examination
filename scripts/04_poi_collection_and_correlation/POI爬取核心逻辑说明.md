## 文件位置

---

## 1. 数据流程概览

```
ground_truth_final_neighborhood_filtered.xlsx
  │
  ▼
按「社区」分组 → 取「谷歌经纬度」均值 → 社区中心坐标
  │
  ▼
每个社区循环 ───→ 7大类别分别查询高德Around Search API
  │                    │
  │                    ├─ 餐饮服务     (types=餐饮服务)
  │                    ├─ 生活服务     (types=生活服务)
  │                    ├─ 购物服务     (types=购物服务)
  │                    ├─ 公司企业     (types=公司企业)
  │                    ├─ 医疗保健服务  (types=医疗保健服务)
  │                    ├─ 科教文化服务  (types=科教文化服务)
  │                    └─ 住宿服务     (types=住宿服务)
  │                    │
  │                    ▼ 每类翻页(最多10页, 每页25条)
  │             原始POI列表(有跨类别重复)
  │                    │
  │                    ▼ 按 id 去重
  │             去重后的唯一POI列表
  │                    │
  │                    ▼ 统计分布 + 过滤噪音类型
  │             最终输出JSON
  │
  ▼
保存为 v2.json (每个社区含 center_location 记录爬取中心点)
```

---

## 2. 核心参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 搜索半径 | **1500** 米 | 高德Around Search的radius参数 |
| 每页条数 | **25** | offset参数, 高德固定最大25条/页 |
| 最大翻页 | **10** 页 | 每类最多翻10页, 即250条/类上限 |
| 目标类别 | 7大类 | 餐饮/生活/购物/公司企业/医疗/科教文化/住宿 |
| API端点 | `https://restapi.amap.com/v3/place/around` | 周边搜索API |

## 5. API请求详情

### 请求URL
```
GET https://restapi.amap.com/v3/place/around
```

### 请求参数
| 参数 | 值 | 说明 |
|------|-----|------|
| `key` | 用户输入的API Key | 运行时交互输入 |
| `location` | `lng,lat` | 社区中心坐标 |
| `radius` | 1500 | 搜索半径(米) |
| `offset` | 25 | 每页条数 |
| `page` | 1~10 | 页码，递增翻页 |
| `types` | 中文类别名 | 如"餐饮服务" |
| `extensions` | all | 返回完整POI信息 |
| `output` | JSON | 返回格式 |

### 翻页终止条件
- 当前页返回的POI数量 < 25 → 已到最后一页，终止
- 当前页数 > max_pages(10) → 达到上限，终止
- API返回 status ≠ 1 → 异常，终止

## 6. 去重逻辑

7个类别的查询结果中，**同一个POI可能出现在多个类别里**（例如一家餐厅可能在"餐饮服务"和"生活服务"中都被返回）。

```python
seen_ids = set()
for poi in all_raw_pois:
    poi_id = poi.get('id', '')
    if poi_id and poi_id in seen_ids:
        continue  # 跳过重复
    seen_ids.add(poi_id)
    deduped_pois.append(poi)
```

- 去重依据: POI的 `id` 字段（高德唯一标识）
- **id 为空的POI不做去重**（极少出现，直接保留）

## 9. 注意事项

1. **API额度**：每个社区需发起 7类别 × 10页 = 70次API请求，92个社区共约 **6440次**请求。高德个人开发者每日配额通常为5000次，建议分批次运行或提高配额。
2. **运行时长**：每次请求间有0.2秒sleep，预计总耗时约 6440 × 0.2 ≈ **21分钟**。
3. **数据时效性**：高德POI数据会动态更新，同一坐标不同时间爬取结果可能存在微小差异（约5%~10%的POI变化）。
4. **与原始数据的差异**：原始版本(`小区周边POI数据_高德_mapped.json`)每类只翻1页(25条)，且不按id去重。新版本数据量约为原来的 **10~20倍**。
